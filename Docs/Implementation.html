响应式体积烟雾：UE5 落地要点

对应工程 GTL-Render-VolumetricSmoke（UE 5.8，C++ 加一个全局着色器模块，不改引擎）。本文按数据流顺序列出《反恐精英2》式烟雾的每一步做法：关卡体素化、三种扩散规则、到达距离场、按事件时间挖空、RDG 光线步进、玩法遮挡和联网同步，并附关键常数、坑点和移植清单，可以直接对照源码搬进自己的项目。原理、业界方案对比与推断依据见 Research.html。

1. 总览

核心思路是：每颗烟只存一份“到达距离场”，其余一切都是这份场加上时间的函数。烟雾弹起爆时，在关卡体素里做一次填充，记下每个体素被烟到达的距离（每格一个字节）。之后的生长、消散、子弹通道和高爆清空都在着色器里按“当前时刻”和几个事件参数现算，不需要改写体素。玩法判定（哨兵视线）在 CPU 上沿线积分同一份场，不读画面。

模块对应关系：SLVoxel（关卡体素与三种填充，纯 C++）、ASLSmoke（每颗烟一个复制 Actor）、ASLSmokeManager（槽位、事件缓冲、CPU 密度查询、向渲染器提交每帧数据）、SmokeLabShaders 模块（FSLSmokeRenderer 场景视图扩展与 Shaders/SmokeLab.usf）、ASLBot（视线与相关性剔除）。

2. 什么走网络

数据载体何时内容

3. 关卡体素化

开局时 FSLVoxelWorld::Build 对整张地图（本工程 104 × 72 × 12 格）逐格做盒体重叠检测，约 50 ms：

  • 新建一个碰撞通道 Smoke（DefaultEngine.ini 里 ECC_GameTraceChannel1，默认 Block）。墙、地面、箱子挡它；角色胶囊体设为 Ignore，否则烟会把人当成墙绕开。
  • 带 SmokePass 标签的 Actor（铁栅、通风口）记为 2：烟可以穿过，但它仍然挡视线和子弹。
  • 格子外：上方和四周视为空气，下方视为实心，所以烟不会从地图边缘以下漏出去。
  • 门开关后只对门附近的区域调用 Rebuild，再让包围盒碰到门的烟按原输入重新填充一次，版本号加一。

渲染器另外拿到一份只有 0 / 1 的 SolidMask，作为 3D 纹理用于太阳遮挡和天空可见度。

4. 扩散：到达距离场

每颗烟有一个 32³ 的局部网格，网格原点 = 起爆体素 − (16, 16, 4)，所以烟可以向上长 28 格、向下 4 格。手雷卡在缝里时，在 2 格内找最近的空气体素作为起点，找不到就不起烟。场里每格存一个字节：到达距离（体素）× 8，255 表示没有烟。

规则算法到达距离特点
A 椭球裁剪椭球内所有非实心体素到起点的椭球度量距离最便宜；顺带用 BFS 统计“漏出”体素数
B 测地填充6 邻域 BFS，限制在椭球内BFS 步数不穿墙，但被挡住的体积就没了，贴墙的烟很薄
C 体积守恒26 邻域整数倒角 Dijkstra，桶队列，直到填满 OpenVolume() 个体素Dijkstra 距离走廊里沿着走廊延伸，房间里自然铺开；结果确定
// 规则 C 的核心（SLVoxel.cpp）
Budget = OpenVolume();                       // 开阔地面上椭球能装下的体素数，常数
Cost[dz][dy][dx] = round(10 · sqrt(dx² + dy² + (dz · RadiusXY/RadiusZ)²))   // 整数，竖直更贵
从起点开始按桶序号（距离 ×10）出队：
    记录到达距离 = 桶号 / 10，Filled++，到 Budget 就停
    对 26 个邻居：跳过实心；斜向一步要求它分解出的每个轴向步都是空气（不准切墙角）
                 新距离 < 旧距离 就放进对应的桶
  • 为什么用整数代价和桶队列：浮点距离加优先队列在不同编译器、不同 CPU 上可能出队顺序不同，填出的场就不一样；“只发输入”模式下各端各自填充，必须逐位一致。整数代价配固定的邻居遍历顺序，结果只取决于关卡体素。
  • 为什么竖直代价更高：比例取椭球的水平 / 竖直半径之比，开阔地面上填出来的形状就是那个椭球，和规则 A 一致。
  • 一次填充 0.3–0.7 ms（955 个体素）。可以放到任务线程里，本工程直接在游戏线程上做。

5. 生长、消散与上传

场不随时间变，变的是“可见半径”。ASLSmoke::Radius(t)：

x      = clamp(age / 1.6 s, 0, 1)           // 慢放生长时 ×4
R(t)   = (MaxDist + 1.5) · (1 − (1 − x)³)    // 先快后慢
寿命最后 2.5 s：R ×= 0.35 + 0.65 · tail，密度 ×= tail     // 从外向里收缩并变淡，寿命 18 s
着色器：density = saturate((R − arrival) / feather) · fade，feather = 2 格

到达距离小的体素先出现，所以生长、消散天然沿着扩散路径：走廊里的烟会一节一节地往前推，门后的烟最后出现、最先消失。

上传到 GPU 前做两圈软膨胀：烟外侧一圈空气体素写入“最近烟体素的到达距离 + 12”（1.5 格），两圈后停止，不写进实心体素。这样三线性过滤在烟的边缘得到一段渐变，而不是体素台阶。所有烟共用一张 542 × 32 × 32 的 R8 三维图集，16 个槽位，x 方向每槽相隔 34 格，中间留 2 格空隙防止过滤串到隔壁槽。

6. 子弹与高爆：事件挖空

子弹和爆炸不改场，只在“当前时刻”的密度上乘一个系数。CPU 的 ASLSmokeManager::DensityAt 和着色器的 Density 用同一套公式，玩法与画面一致。

// 子弹（每条：起点 S、终点 E、age = (t − t0) / 1.6 s、半径系数 k）
r       = 到线段 SE 的距离 · 0.05 / 2.54 · k        // 20 Hammer 单位（约 51 cm）处 r = 1
nearEnd = 1 − saturate(到 E 的距离 / 254 cm)          // 弹着点附近 2.5 m 逐渐闭合
carve   = smoothstep(0, 0.5, 1 − saturate(age + saturate(r + nearEnd)))
density = lerp(density, −0.05, carve)                // 中心清到 0，随 age 收拢

// 高爆（每个：位置 B、age = t − t0 秒、位掩码）
pulse   = (1 − smoothstep(0, 2, age))^128            // 冲击前沿
k       = smoothstep(200u, 240u, |P − B| + pulse · 250u) + (回填 ? smoothstep(0.5, 5, age)^1.8 : 0)
density ×= lerp(0.02, 1, saturate(k))                // 200 单位（约 5 m）内清到 2%
  • 只记录穿过烟的射击：服务器先用线段和烟雾包围盒求交，不相交的射击不进缓冲，16 条够用。
  • 本地预测：开枪的客户端立即把自己的子弹放进 LocalBullets，服务器的同一发到达后（同一射手、落点相差 50 cm 以内）去掉本地副本，所以开枪即刻看到通道。
  • 高爆位掩码：对爆点 250 单位范围内的每颗烟，服务器从爆点向那颗烟的起爆点上方 80 cm 做一次 Smoke 通道射线检测；没被挡住，或者爆点本身就在烟里，才把这颗烟的位加进掩码。墙后的烟不受影响（CS2 修过“高爆隔墙推开烟雾”的问题）。掩码随事件复制，客户端不需要再做检测。
  • 通道中心必须清到 0：15 m 厚的烟里残留 5% 的密度仍然不透明。曲线用 smoothstep(0, 0.5, ·)，中心完全清空，再随 age 收窄。

7. 渲染管线

FSLSmokeRenderer 继承 FWorldSceneViewExtension，在 PrePostProcessPass_RenderThread 里用 RDG 插入三个通道，结果预乘混合进场景颜色，排在色调映射之前，所以自动跟随曝光。游戏线程每帧用 SetFrame 提交一份 FSLRenderFrame（烟雾列表、事件、灯光、开关），渲染线程拷贝后使用。

光照缓存（LightCS）

Incident(P) = Sky · (1 − 0.45·D) · lerp(0.18, 1, SkyVisibility(P))
            + Sun · MS(SelfShadow(P)) · WorldSunVisibility(P)
            + Σ 灯光 · 窗函数 / d² · MS(沿灯方向 4 步的烟透射)
SelfShadow  = exp(−1.1 · Σ 朝太阳 6 步、每步 50 cm 的密度)
MS(T)       = T + 0.3 · T^0.2          // 多次散射近似：厚烟内部保持灰白，不发黑也不被灯光染色
SkyVisibility：天顶和 4 个 45° 方向各在关卡体素里走 10 格，按开阔程度加权
WorldSunVisibility：朝太阳在关卡体素里走 16 格

结果写进与图集同布局的 PF_FloatRGBA 三维纹理。步进时按各烟的基础密度加权读取，每个样本不再朝光源步进。面板的“逐采样阴影射线”把这一步挪进步进循环，作为对照：画面相近，耗时成倍增加。

步进（MarchCS）

  • 先用所有烟的包围盒和射线求交，只在 [进入, 离开] 区间里步进，终点截到场景深度前 2 cm。步长 10 cm，最多 320 步，透明度到 0.995 提前退出，消光系数 σ = 0.035 / cm。
  • 起点按交错梯度噪声（IGN）抖动半个步长以内，消除分层条纹。抖动留下的颗粒由合成通道的宽滤波吃掉。
  • 细节噪声：64³ 的 RG8 纹理（CPU 上生成两层 Worley），先做一次低频的采样位置扰动（幅度 0.9 格），再乘一层侵蚀。玩法密度下限开启时，侵蚀只作用在离表面 3 格以内的边缘带，烟芯永远不被噪声削透。
  • 噪声坐标必须是世界坐标。着色器拿到的都是 translated world（世界坐标 + PreViewTranslation），直接拿它采噪声，细节会跟着镜头滑动。传入 PreViewTranslation 先减回去。

合成（CompositePS）

每个全分辨率像素取周围 4×4 个低分辨率样本，权重 = 半径 1.5 的帐篷函数 × exp(−40 · 相对深度差)。如果没有一个样本的深度和本像素相差 4% 以内（墙角、枪管边缘），就在这个像素上用全分辨率重新步进一次（CS2 的 full-res pass）。帐篷比双线性宽，1/4 分辨率下的抖动不会放大成 4×4 像素的网点。

8. 玩法遮挡与哨兵视线

ASLSmokeManager::SmokeLength(A, B) 只在线段穿过烟雾包围盒的那一段上，每 20 cm 采一次无噪声的密度（含子弹与高爆挖空），累加“等效满密度长度”。哨兵的判定：

  1. 距离 50 m 内、在视野里（当前朝向 ±65°，或岗位朝向 ±70°）。
  2. 对胸口和头部做 Visibility 射线检测，任一点没被几何挡住。
  3. 那条视线上的烟长度 < 250 cm（BotSmokeBlockCm × 0.5）。CS2 的机器人用 bot_max_visible_smoke_length 200（Hammer 单位）。

因为这里不读画面，关掉“绘制烟雾”后哨兵照样看不见你；不同画质、不同显卡、开不开噪声，都得到同一个判定。

9. 同步与相关性剔除

两种同步方式

服务器下发结果（默认）只发输入，各自填充
每颗烟的流量24 + 约 610 字节，只发一次24 字节
客户端计算解压完整填充一次
一致性前提无各端关卡体素与填充代码逐位一致
门、可破坏物服务器重算后重发每端都要在同一时刻看到同样的关卡变化

两种方式下服务器都复制自己结果的 CRC32（ServerFieldCrc），客户端拿本地场的 CRC 比对，界面上显示“与服务器不一致 N 颗”。面板的“本机关卡数据差异”让这台客户端把铁栅当成实心，用来演示只发输入时一处关卡差异就能让两端的烟不一样；CS2 在 2024 年 10 月改为下发结果，也是出于同样的原因。

相关性剔除

bool ASLBot::IsNetRelevantFor(RealViewer, ViewTarget, SrcLocation)
    未开启 / 已死亡 / 本地控制器 → 引擎默认
    hidden = SmokeHides(SrcLocation)       // 头、胸、脚，加 0.25 s 后的预测位置，6 个点都在 ≥ 250 cm 的烟后
    不 hidden → RelevantUntil[viewer] = now + 0.5 s
    now < RelevantUntil → 引擎默认，否则 false
  • 判定偏乐观：只有 6 个探测点全部被烟挡住才剔除，宁可多发也不要让对手在烟边缘“闪现”。几何遮挡交给引擎原有规则，这里只管烟。
  • 0.5 s 迟滞防止烟边缘来回切换。NetDriver 的 RelevantTimeout 调成 0.6 s，不相关的 Actor 通道才会及时关闭；默认值 5 s 时演示看不出效果。
  • 本工程关闭了 Iris（net.Iris.UseIrisReplication=0），IsNetRelevantFor 走传统复制路径。使用 Iris 的项目要改写成过滤器（UNetObjectFilter）。

自测里客户端站在中路，在自己和两名哨兵之间起一颗烟后，客户端上的 ASLBot 从 3 个变成 1 个；透视视角只能画出它真正收到的那一个。

10. 射击：枪口与瞄准点

AimDir   = VRandCone(镜头朝向, 扩散角)           // 扩散 = 0.35° + 移动 2.4° + 后坐
AimPoint = 镜头沿 AimDir 的射线检测命中点（或 120 m 处）
Start    = 第一人称枪模的枪口                    // Rifle1P 局部 (0, 55, 10)
End      = 枪口到 AimPoint 的射线检测命中点
本地：曳光 + 预测通道（Start → End）；服务器：ServerFire(Start, Dir)，起点离眼睛超过 1.5 m 时改用眼睛

这是常规 FPS 的做法：准星决定打哪里，子弹从枪口出来。烟里的通道也是枪口到落点这一段，所以从玩家视角看，通道从右下方斜着通向准星。其他人看到的曳光从第三人称枪模的枪口出发。

12. 坑点清单

  • 噪声在 translated world 里采样：细节跟着镜头滑动。先减去 PreViewTranslation。
  • 灯光单位不一致：C++ 里新建的点光源默认是无单位亮度。着色器若按坎德拉理解同一个数，烟比墙亮几十倍。设 IntensityUnits = ELightUnits::Candelas。
  • 灯光不被烟衰减：太阳有自阴影而灯没有时，厚烟内部和子弹通道的内壁会被灯光染成暖黄色。灯光也要走几步透射，再配合多次散射近似。
  • 通道没清到 0：残留 5% 的密度在厚烟里照样不透明，通道看不穿。
  • 浮点 Dijkstra：出队顺序可能因平台而异，只发输入时两端填出不同的烟。用整数代价加桶队列。
  • 斜向穿墙角：26 邻域如果不检查分解出的轴向步，烟会从两块墙板的对角缝里漏过去。
  • 体素台阶：直接用最近体素采样或不做软膨胀，边缘是一级级的方块。三线性过滤加两圈软膨胀、2 格羽化，再加一次低频的采样位置扰动。
  • 低分辨率网点：IGN 抖动在 1/4 分辨率下会放大成 4×4 网点，上采样要用比双线性更宽的滤波。
  • 相关性剔除不生效：RelevantTimeout 默认 5 s；Iris 开启时 IsNetRelevantFor 不被调用。
  • 天光实时捕获：运行时创建的 SkyLightComponent 要在 RegisterComponent 之前设好 bRealTimeCapture，否则阴影里一片漆黑。
  • 截图与状态切换在同一帧：截图拿到的是整个游戏 Tick 之后渲染的那一帧，同一步里的开关变化会出现在截图里。自测脚本把状态切换放到截图后的下一步。
  • F1–F12 被引擎占用：在 DefaultInput.ini 里写 !DebugExecBindings=ClearArray。

13. 移植清单

  1. 加一个 Smoke 碰撞通道，给能透烟的物体打 SmokePass 标签，角色胶囊体对它设 Ignore。
  2. 拷贝 SLVoxel.h/.cpp（纯 C++）。按自己的单位调 SL::VoxelCm、椭球半径和寿命；开局对地图调用 Build，可破坏物或门变化时对局部调用 Rebuild。
  3. 烟雾 Actor：服务器填充，按需要选“下发结果”或“只发输入”，复制 CRC 以便检查一致性。
